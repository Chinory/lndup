class ByteMap {
	constructor() {
		// 使用 Buffer 作为快速索引表 (byte -> array index)
		this.B = Buffer.alloc(256);
		this.B.fill(255); // 初始化为 255 (表示空)
		
		// 使用 Array 存储实际的值，可以动态扩容
		this.A = [];
	}

	set(key, value) {
		if (typeof key !== 'number' || key < 0 || key > 255) {
			throw new Error('Key must be a byte (0-255)');
		}

		const index = this.B[key];
		if (index !== 255) {
			this.A[index] = value;
		} else {
      if (this.A.length < 256) {
        this.B[key] = this.A.length;
        this.A.push(value);
      } else {
        this.A[index] = value;
      }
		}
	}
}

取值范围很重要。一开始，B中只有255。这时用户以任意key设置的时候，B中会出现一个0，你不要管它在B的哪里，你只需关心B的值也就是index的取值范围。

当用户第二次设置的key的时候：如果是旧key，则它的值index一定不是255，其必然在`[0,0]`范围内，因此会进入设置A的分支，就不会影响B的取值范围，所以我们会发现，只要用户提供的不是新key，则index就不会是255，因此就B不会被更新，因此`key=>index`的所有映射关系都不会改变，而单纯设置A也不会增加其长度，因为index的取值范围是`[0,0]`，而这没有超出A的长度。

当用户第三次设置key的时候，如果它是新key，则`const index`获得255，则进入`B[key]=A.length=1`，使得B的取值范围变成`[0,1]`，而且由于它是从255变过来的，所以0不会被消除掉，

当用户第四次设置key的时候，如果它是旧key，则它的取值范围是`[0,1]`，那么进入`A[index]=value`的分支，就不会改变B。

当用户第五次设置key的时候，如果它是新key，则`const index`获得255，则进入`B[key]=A.length=2`，使得B的取值范围变成`[0,2]`，而且由于它是从255变过来的，所以0和1都不会被消除掉。

我们可以发现，每次B的取值范围拓展时，都是从255转过来的，不会改变已经不是255的取值，所以说：B左侧的取值范围其实一直是密集的，并且它的上限恰好就等于A的最大index，或者说A的长度-1。

你可以看到这是一个稳步推进的态势，所以，你说的多个键指向数组同一位置是不存在的，除了255这个特殊值，但是，它又总是会被特殊处理。

直到某次push后，A的长度变为255。根据之前的归纳，我们知道B左侧的取值范围此时将会是密集的`[0,254]`，也就是说，B中此时只剩下一个从未被设置过的位置，其值是255。此时用户再设置一个新key，我们不必知道此时key的具体值，但它一定会命中这个255，此时，这个255会被重复设置为255，虽说数值上没有变，但你应该能理解，从逻辑上来说，B左侧的密集取值范围变成了`[0,255]`，终于完成了全覆盖，并且根据之前的归纳，此时所有`key=>index`的映射都是独立完整的。并且接着马上执行`A.push()`后，A的长度变为256，此时所有value都已被初始化。

唯有在这一刻开始，再次进入这个修改B、新增A的分支才会是破坏性的，执行一次，就会导致B无论是键还是值的取值范围都变得不密集，中间被挖了个洞。而这就是我添加那个`if (this.A.length < 256)`要防范的。

可以说，在此时，index=255 已经不再特殊，它已经变成了一个普通的index。
